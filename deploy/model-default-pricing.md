# 模型广场：全局默认计费标准

模型广场的“编辑底层默认价 / 新增计费标准”管理全局计费默认值，不是展示价格、分组倍率或供应商官方价。仅保存价格不会创建账号映射、路由或可调用目录项。

## 层级与单位

- Token 解析保持分组价卡优先，其次渠道价卡，再到全局默认价。分组价卡命中后不再叠加渠道价卡；缺失 Token 字段继承全局默认。
- 全局默认价是 **管理员显式字段 → 系统有效默认价**。后者继续保留目录/缓存、fallback 文件、override 文件和代码策略；文件 override 只是系统文件层的最高优先级。
- 图片/视频保留既有专用分组价、分辨率、倍率及渠道规则。管理员标准只取代底层默认来源，Grok 的代码默认值不会抢先覆盖人工标准。
- 表单 Token 金额单位为 **USD / 百万 Token**，API 和存储为 **USD / Token**。输入、输出、缓存 5m/1h、图片输入/输出 Token 均按此换算。
- `per_request_price` 为 **USD / 次**；`image_price_1k/2k/4k` 为 **USD / 张**；`video_price_480p/720p/1080p` 为 **USD / 秒**。视频成本为每秒单价 × 时长 × 数量，再按原有规则乘倍率。
- 跨计量模式的专用分组媒体价以条件基准价展示，不把每张/每秒价格混入 Token 或按次的样本比价。
- 现有分组/渠道 video 价卡沿用既有结算语义，本功能没有批量迁移或改写这些价卡。新增全局视频标准和报价明确使用 `per_second`。
- 对原本没有完整 Token 基准的新标准，未设置的缓存写入/读取继承普通输入单价，未设的 1h 写入继承 5m 写入；这些是有效价回退，不写成虚假的人工字段。显式 `0` 或缓存折扣始终优先；已有完整系统标准的缓存行为不变。
- priority、长上下文策略等高级字段保留系统值，当前表单不回填它们。音频、搜索等独立附加收费仍由原专用配置管理。

## 操作与权限

在模型行编辑已有标准，或点击独立“新增计费标准”手填 ID；未接入能力目录的模型可在人工标准列表中维护。模型 ID 按 trim/小写归一化，保留斜杠、点、冒号和版本后缀；不支持通配规则。

- 省略 patch 字段：不修改已存覆盖。
- 显式数字 `0`：该字段免费，不是缺价。
- 显式 `null` / “恢复继承”：移除该字段覆盖。
- 新 Token 标准须有明确输入和输出单价；新媒体标准须覆盖本模式所需档位。家族估价不等于精确标准，不能替代新 Token 标准的两侧必填项。
- 没有合法系统基准时，服务器拒绝撤掉唯一可计费标准；没有强制删除按钮。下架需先停用调用入口并处理在途请求。
- 写入遇到 409，弹窗保留草稿，显示服务器新版本的差异；管理员确认后才允许再次保存，不自动重试覆盖。
- 价格与展示设置的版本、草稿和保存动作相互独立；价格保存只刷新人工列表/公开报价，不重置隐藏、置顶、排序草稿。

权限目录新增 `models.pricing.read` / `models.pricing.write`（迁移 247）。迁移仅注册定义，不授予任何已有管理员新权限。`enforce` 模式下，展示编辑者不会自动获得全局改价权限；`disabled` 模式继续保留普通管理员的既有角色授权行为，super-admin 遵循现有规则。API 经过管理员认证、精确权限映射、审计和既有合规中间件。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/admin/model-plaza/pricing?model_id=...` | 系统基准、精确人工记录、有效价、来源、单位、已存/已加载版本 |
| GET | `/api/v1/admin/model-plaza/pricing/overrides?search=...&page=1&page_size=20` | 人工标准搜索和分页（含目录外模型） |
| PUT | `/api/v1/admin/model-plaza/pricing` | `model_id`、字符串 `version`、白名单 `patch` |
| POST | `/api/v1/admin/model-plaza/pricing/reset` | `model_id`、`version`、可选 `fields`，受恢复保护 |

ID 放在 query/body，包含 `/` 的模型无需改变路由。单次请求体限制 16 KiB；快照限制 10,000 条记录和 8 MiB。默认价版本不与广场展示设置版本共享。

## 持久化、生效与备份

数据位于现有 `settings` 表的 `model_default_pricing_overrides` 键，格式包含 `schema_version: 1`、单调 `revision` 和 `models` 稀疏覆盖表。

1. 保存读取当前 JSON，校验目标模型有效标准，以数据库 CAS 比较旧 JSON 后提交新 revision。
2. 提交成功才发布本实例不可变快照；慢请求不能把较新快照换回旧版本。数据库/校验失败不改变运行时价格。
3. 启动时必须成功加载并校验人工层才能接受请求。运行期每 **3 秒**刷新一次，数据库读取有 2 秒超时；健康实例通常在 **5 秒内**收敛。错误保留最后有效快照并告警。
4. 管理端区分保存版本和本实例加载版本；不代表所有实例都已成功加载。远程价格同步和文件热更不会清除数据库人工层；请求计费不逐次查询数据库。
5. 常规数据库备份会包含该 settings 行。恢复时应同时备份/恢复系统默认价格文件与应用版本，先停用相关流量。**恢复到较早 revision 后重启所有实例**，不要期待运行中的实例接受版本倒退；恢复完成后核对管理详情和预检再开放流量。
6. 不通过手改运行时目录缓存管理人工价，也不要绕过管理 API 修改 JSON。整库或该行的恢复应使用现有受控备份流程，并保留完整 JSON，不只备份有效价格展开值。

改价不回溯重算 usage、余额或历史账单。单次解析/算费使用一个人工版本，但本功能**不保证预检到结算之间的完整在途锁价**。价格审计复用现有异步审计链路，不是与 settings CAS 同事务的账本。原 OpenAI 缺价结算兼容分支未被改造成全链路 fail-closed；新增完整标准校验和恢复保护避免通过此入口直接撤成无价。
