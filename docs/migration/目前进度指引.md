## 2. 实施顺序（A 阶段）

### A0：接手、来源与证据冻结

1. 记录 branch/HEAD/origin/VERSION/工作树、工具版本、用户来源路径。
2. 保存当前三份文档快照；为本轮创建独立 evidence 目录，不覆盖旧报告。
3. 对 Personal 与官方候选各做一次文件 manifest/hash；排除 `.git`、`node_modules`、`dist`、缓存、运行时生成树，但把排除规则写入 manifest。
4. 建立文件状态：`BYTE_EQUAL`、`EOL_ONLY`、`CONTENT_DIFFERENT`、`PERSONAL_ONLY`、`UPSTREAM_ONLY`。
5. 如恢复官方 0.2.1，追加三方状态：`MERGE_REQUIRED`、`ALREADY_EQUIVALENT`、`PERSONAL_OVERRIDE`、`TEST_ONLY_REQUIRED`、`NOT_APPLICABLE`。
6. 任何 hash、路径、版本冲突都先登记为事实，不在代码里“顺手修正”。

### A1：Personal 不可退化合同

建立一张符号级矩阵，至少覆盖：

- 商城库存、购买次数限制、履约幂等、结算和批量图片额度。
- 支付实例绑定、迟到/重复回调、主动补偿、退款 attempt/hold/人工复核。
- 临时额度 FEFO、永久余额、负余额、事后扣款、银行借款/兑换/还款/账本。
- 返利、签到、订阅、quota、内容审核、Intent Classifier、管理路由、菜单和 feature flag。
- Personal 权限、DTO 裁剪、前端页面、既有 fallback、错误语义、部署镜像和版本显示。

每条合同必须给：Personal 路径/符号、官方候选路径/符号、差异类型、保留/增量/替代理由、测试入口、是否需要 DB/APP。

### A2：SQL、Ent、raw 与生成代码

1. 对所有 `.sql` 进行 filename、原始字节 SHA-256、`TrimSpace` checksum、排序和迁移注册核对；原历史 SQL 不重写、不重编号、不改换行来“修 hash”。
2. 特别评审官方：
   - `235_group_model_allowlist.sql`：`groups.models_list_config` 重命名为 `model_allowlist`。
   - `236_group_model_allowlist_repair.sql`：兼容 235 已记账但 schema 回退、两列并存或两列缺失的修复，并保证新列 `JSONB NOT NULL DEFAULT '{}'`。
   - `237_add_minimax_platform.sql`：扩展 `user_platform_quotas`、`composite_model_routes`、`channel_monitors`、`channel_monitor_request_templates` 的 provider/platform CHECK。
3. 对 Personal 独有 16 个 SQL 建立保留清单，不因官方目录缺少它们而删除或重排。
4. 评审 `ent/schema/group.go`、usage/channel/provider 相关 schema、生成实体、repository insert/select/scan/default、DTO/serializer 和启动迁移器。
5. 若只获 CODE_ONLY 权限：使用 SQLmock、静态 checksum、生成前后 diff、`go test -c`；不得连接项目 DB、执行真实 DDL、自动迁移或启动应用。
6. 只有 B0 另行批准后，才计算目标库 `pending/orphan/mismatch` 并执行完整迁移。

### A3：基础模型、Group 与 provider

- 先合并 domain/constants/request model，再接 repository/cache/service/handler，最后接前端。
- 官方新增/候选重点包括 `model_allowlist.go`、`group_model_allowlist.go`、`openai_models_handler.go`、`channel_cache.go`、MiniMax 平台及 provider 相关文件。
- Group allowlist 要同时验证“模型列表展示过滤”和“请求准入”，并定义 simple mode、空值、通配符、排序、去重、跨平台、创建/复制/更新/清空、越权和缓存失效。
- Personal `models_list_config` 当前是展示配置；官方 `model_allowlist` 同时影响展示和请求准入。不得自动把旧 enabled 配置升级为准入限制；须先确定显式 opt-in/兼容窗口，再处理 235/236、DTO、middleware、cache、WS 首帧和后续 `response.create`。
- provider 归因必须从选择、请求、响应、usage、存储到统计保持同一身份；新增 MiniMax 不得扩大既有额度、权限或 composite route 范围。

### A4：协议、WS、Bridge 与插件

以状态机而不是文件复制实现：

1. 请求是否已发送：`RequestSent` 与错误路径保持准确。
2. 下游是否已写：不能因响应写失败再次向上游发送。
3. owner/claim/refresh/delete、抢占、取消、重连、continuation/encrypted、replay、心跳和 terminal 状态必须原子且可重放。
4. 每个 turn 的 usage、slot、统计和账务只能发生一次；失败/部分响应/客户端取消要明确是否收费。
5. 保留 Personal 已有 gateway、WS、Bridge、cyber、安全、代理和账务语义；官方新增工具名、Codex transcript、Ollama/Grok 等按协议边界增量接入。
6. 共享 `service` 文件只能由主代理或唯一负责人整合；不能让多个代理并行改同一 shared service 后各自跑宽测试。

### A5：计费、Model Plaza 与统一 usage

官方定价能力只能作为候选功能，不能覆盖 Personal 业务政策。先形成可审计规则表：

- input/output/cache/image/video 分项和互斥拆分。
- `standard/fast/priority/flex`、reasoning effort、max reasoning、long-context 阈值和显式 0 关闭语义。
- channel/group/account multiplier 的优先级、是否快照、是否只应用一次。
- 预检与结算是否引用同一 `PricingAt`/请求价格快照。
- 统一账务与旧路径的唯一写入责任、请求 ID/异步任务幂等、失败回写、余额守恒和负余额政策。
- 官方 `model_plaza_service.go` 的参考价、Intervals、LongContextBasis、TimePricing 如何映射到 Personal `channel_plaza`；展示字段不能反向修改 Personal 计费配置。
- 官方 `account_upstream_billing_rates.go` 只表示倍率数据的读取/缓存/ETag/API 合同，不足以推导实际收费数字；未获产品决策前保持 UNKNOWN。

最低 CODE_ONLY 矩阵：输入/输出/cache、图像/视频、tier、reasoning、长上下文 `< / == / >` 阈值、显式 0、账号/组倍率、请求重放、统一 usage 单写、计费失败、Model Plaza nil/命中/分时/分页/ETag。

### A6：Handler、DTO、权限与安全

- 先列所有受影响 handler、DTO、serializer、公开/管理员路由和 middleware。
- 明确 `lite/full/admin` DTO，禁止把管理端 pricing/fallback/routing/allowlist 整体泄露给公开接口。
- 验证非法 tier/allowlist/platform 不调度、不向上游发请求、错误码和错误体稳定。
- 图片/代理安全继续要求每跳 DNS 与实际 checked-IP 一致、拒绝回环/私网/link-local/空解析、Host/SNI 正确、超时/大小/字节识别和关闭兼容。
- feature flag 只改变已获准页面/能力，不覆盖 Personal 权限、菜单、审核、Classifier 或资金路径。

### A7：前端、Classifier、部署与 CI

1. 前端保留 Personal `/mall`、`/check-in`、`/bank`、`/finance` 及管理银行/财务路由、权限和菜单。
2. 官方白名单辅助器的形状为 `enabled + models[]`，候选请求至少含 `mode/groupID/platform`；与 Personal `models_list_config` 分离映射，不能只做字段替换。
3. 平台切换先 reset，异步候选按 mode/group/platform 丢弃过期响应；创建/更新/复制/清空和开启但空选中均要有行为测试。
4. 官方 `package.json` build 新增 `check:i18n`；融合后检查新增 route/title/description、白名单错误/空态和 `common.pageDisabledByAdmin`，同时保留 Personal 本地化。
5. CI/release/GoReleaser/Docker/embed/版本文件统一使用 `0.2.4-p1`，依赖锁文件只有在确有依赖变更时更新；不要因官方 `package.json` 差异覆盖 Personal 功能。
6. Classifier 继续按 off/shadow/enforce/on-error 和模型包边界单独验收；未改源码不能自动继承旧证据，后端 DTO/权限变化时必须做合同关联评估。

### A8：同树验收、候选冻结与停止

- 固定候选后，停止共享写入，重复生成 Ent/Wire；任何生成漂移先回实现阶段处理。
- 依次执行：窄 CODE_ONLY → 受影响 package → 全后端 build/lint → DB/APP 逐包 `go test -c` → 前端四门禁 → Classifier/产物 → 总 manifest。
- `go test -run '^$'` 不代替只编译；有外部 TestMain/init 的包使用 `go test -c` 并标 `COMPILED_NOT_RUN`。
- 失败必须记录准确命令、cwd、工具版本、tag、regex、退出码、顶层/子测试数、日志、源 hash、未验证边界；不把不同集合计数相加。
- 候选源、生成代码、SQL、依赖、版本、配置或测试合同发生影响验收的变化，立即生成新 candidate，不沿用旧结果。

## 3. 代理与写入合同

### 3.1 主代理职责

主代理一次建立并维护：source identity、Git 状态、官方/Personal manifest、SQL 清单、TestMain/init、测试入口、受保护业务矩阵、唯一共享写域、证据索引和总门禁。

### 3.2 子代理任务卡

最多并行 6 个；每个任务必须有不重叠的读取/写入范围。默认先派短时只读探子；实现代理只有在明确授权后使用。任务卡必须写：

- 任务 ID/一个具体目标；
- 已知事实与源 hash/时间；
- 3～8 个绝对路径及符号/行段；
- 精确写入白名单；
- 最多一个邻接文件；
- 禁止读取/禁止动作；
- CODE_ONLY/只编译/禁止 DB-APP-外部调用边界；
- 专属证据路径、预算、输出上限；
- 返回结论/UNKNOWN、file:line、符号、最短原文、命令/退出码/计数、源 hash、未验边界。

## 4. 证据与日志规则

每个阶段建立独立目录，例如：

`D:/Codex_Program/Personal_Sub2/fusion-0.2.4-plan-evidence/<candidate>/`

- `index/project-index.json`：HEAD/branch/VERSION/源 hash/排除规则/写域。

## 5. 测试分层与外部边界

| 类别 | 允许内容 | 当前规则 |
|---|---|---|
| CODE_ONLY | 纯逻辑、内存替身、sqlmock、miniredis、httptest、前端 mock、静态契约 | A 阶段优先；必须绑定候选 hash |
| COMPILE_ONLY | `go test -c`，用于含外部 TestMain/init 的 DB/APP 包 | 结果只能写 `COMPILED_NOT_RUN` |
| DB_REQUIRED | PostgreSQL/真实迁移/真实 Redis/集成测试 | 本轮未授权；必须 B0 明确目标与恢复方案 |
| APP_REQUIRED | server/Compose/自动迁移/应用联调 | 本轮未授权；不得靠删环境变量伪造隔离 |
| EXTERNAL_AUTH_REQUIRED | 真实 OAuth/provider/payment/webhook/upstream | 本轮未授权；沙箱也需明确授权 |

禁止：宽 `go test ./...` 触发外部 TestMain、`go test -tags integration`、自动迁移、schema create、Compose up、server/setup/init、生产 DB/Redis 查询、真实上游/支付/通知/收费请求。
